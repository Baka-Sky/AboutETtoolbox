五、注册表操作说明（重点：不是“修改注册表”）
======================================================================
程序导入的注册表相关 API（来自静态链接的易语言运行库，属常规导入）：
    RegOpenKeyExA、RegQueryValueExA、RegQueryValueA、RegCloseKey  —— 读取
    RegCreateKeyExA、RegSetValueExA                              —— 导入但未发现调用所需的路径常量
程序中出现的注册表路径常量只有 3 条，且都是【读取】：
    1) SOFTWARE\Microsoft\Windows NT\CurrentVersion\ProductName   （判断是 Win10/11/Server 等）
    2) SOFTWARE\Microsoft\Windows NT\CurrentVersion\CSDVersion    （判断 SP/补丁版本）
    3) SOFTWARE\Microsoft\Windows NT\CurrentVersion\CurrentBuild  （判断系统 Build 号）
用途：用于“系统兼容性判断”，对应界面提示语：
    “您当前的系统版本不兼容这个工具哦！”、“32位系统不兼容这个工具哦！”（含 “获取失败，请检查版本:”）
未发现：开机自启项、服务注册、Shell 扩展注册、解除/修改系统安全设置等写入注册表的路径常量。

【配置写在哪里】——不在注册表，而是在程序自己目录下的 INI：
    工具箱配置（请勿删除，留着可以自己改哦）.ini   ← 主题/音效/背景/开关等（读写）
    hwinfo.ini                                     ← 硬件检测结果缓存（写）
    （写 INI 用的是 WritePrivateProfileStringA / GetPrivateProfileStringA，属正常配置读写）

注意：由于易语言“静态编译”会直接把运行库里的 RegSetValueExA 等带进导入表，
      因此“导入表里出现写注册表函数”≠“程序真的写注册表”。
      本次静态分析未找到任何用于写入的注册表路径，故判定为只读。

十一、第二轮深度核查（IAT 交叉引用 + 依赖组件 + 本地文件）
======================================================================
为排除“导入表里有函数、但代码其实没调用”的误判，本轮直接做了 IAT 交叉引用，定位每个
敏感 API 的真实 call 点，并逐一还原其上下文。

1) 注册表 API：真实调用点与其归属
   - RegOpenKeyExA / RegQueryValueExA / RegQueryValueA：调用点成立，
     打开标志为 0x20019（KEY_READ，只读）。用于读取第五节列的 3 条系统版本路径。
   - RegCreateKeyExA / RegSetValueExA：调用点成立，但全部集中在同一个“通用注册表助手函数”
     （0x4b4f28 / 0x4b4f42 / 0x4b24f1）。该函数把子键名硬编码为字符串 "software"，
     配合 HKEY_CURRENT_USER(0x80000001) 使用；它周围的字符串是 MFC 运行库字符串
     （CObject、CMapStringToPtr、commdlg_ColorOK、commdlg_FileNameOK、.INI、.HLP、
      H:mm:ss、December、November…）。
     判定：这是【随静态链接进来的 MFC / 易语言运行库自带的通用实现】。
     程序自身不存在任何用于“写入”的注册表路径常量，因此不会用它写开机启动项。
   - 全文件重扫（ASCII + GBK + UTF-16 三种编码）：不存在 Run / RunOnce / Services /
     AppInit_DLLs / Winlogon / Shell\Open / schtasks / bcdedit / netsh / hosts 等
     任何持久化或系统篡改相关字符串。

2) SetWindowsHookExA：真实调用点（2 处）
   两处都是：先 call GetCurrentThreadId 取当前线程 ID 作为 dwThreadId，hMod=0，
   idHook=5（WH_CBT）。这是【线程级 UI 钩子】，皮肤库/窗口子类化常用；
   且程序未导入 GetAsyncKeyState / GetKeyboardState，不构成键盘记录行为。

3) ShellExecuteA：调用点 push 的操作串正是字符串 "open"（VA 0x707d00），
   即“用系统默认程序打开文件/链接”，无隐藏参数。
   CreateProcessA / WinExec 调用点均为“启动外部程序”，与工具箱定位一致。

4) 依赖组件：硬件检测引擎.dll（与 EXE 同目录，程序运行时会调用它）
   - 文件描述：图吧工具箱硬件检测引擎；公司：曙光工作室；版本 1.0.0.0；
     导出函数：Hwinfo、Hwinfo_C、dllversion。属于【第三方】组件（图吧工具箱），
     并非本程序作者编写。
   - 该 DLL 被 ASPack 加壳（存在 .aspack 段、.text 熵 8.00、导入表仅剩极少桩函数、
     真实 API 运行时动态解析），并且【没有有效的数字签名】（其“安全目录”指向的不是
     Authenticode 签名，而是区段数据）。
   - 影响：加壳后无法用静态方法完全确认其内部行为。
   - 背景：它是有公开来源的“图吧工具箱·硬件检测引擎”，本程序仅用它读取硬件信息，
     并把结果写入同目录 hwinfo.ini（本次核查到的 hwinfo.ini 内容为 CPU/主板/系统等常规信息）。
   - 建议：如对第三方 DLL 不放心，可在沙箱/虚拟机中单独观察其行为，或改用其它硬件信息工具。

5) 本地配套文件核查
   - 更新日志\index.html、app.js、data.js：普通更新日志页面；仅外链 cdnjs 的
     font-awesome 样式表和网易云音乐播放器 iframe（music.163.com/outchain/player），
     未发现 eval / atob / 动态脚本注入 / 隐藏跳转等可疑脚本。
   - 更新日志\debug.log：仅为“事件跟踪 Provider 注册失败”的日志文本，无敏感内容。
   - 工具箱配置（请勿删除…）.ini、hwinfo.ini：程序自身目录下的配置与硬件缓存（正常读写）。

6) 二轮结论（结论不变，且证据更确凿）
   主程序 万物工具箱.exe 未发现木马 / 后门 / 持久化 / 键盘记录 / 进程注入 / 下载执行代码；
   注册表仅用于“读取系统版本”，配置写在自身目录的 INI。
   需要留意的只有两点：① 它携带并会启动大量第三方工具（含激活、提权、系统底层、远控）；
   ② 第三方组件 硬件检测引擎.dll 为加壳且无签名（属图吧工具箱的公开组件）。
